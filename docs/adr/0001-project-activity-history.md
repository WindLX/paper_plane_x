# 项目活动历史由项目自身持久化

项目活动历史存放在 `project_activities` 表中，由项目拥有，独立于旧的 `projects.operation_logs` JSON 列和论文处理任务。我们这样决定，是因为活动历史必须在任务记录被删除、论文与项目解除关联之后依然可查，而按项目、类别、状态和时间过滤也需要索引，JSON 列与任务表都给不了。代价是活动成为任务状态的第二份记录：因此活动在写入时快照任务状态，并通过 `task_id` 与 `task_exists` 表示关联任务，而不是在读取时回连任务表。

## Considered Options

- 读取时从处理任务和 operation_logs 派生活动：无法在任务删除或解除关联后保留历史，也无法支持带索引的筛选与分页。
- 复用处理任务表存储活动：任务只存在于论文处理生命周期内，无法表达文件、导出、项目级事件，也不符合“删除任务不等于删除历史”的语义。

## Consequences

- 删除任务、删除论文或解除项目关联都不得级联删除活动行；活动单独随项目生命周期清理。
- 迁移把已有 `operation_logs` 回填为活动，并使用确定性 ID 保证与实时写入不重复。
